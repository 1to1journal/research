# One to One Journal

একটি সম্পূর্ণ কার্যকরী রিসার্চ জার্নাল ওয়েবসাইট, যা সার্চ ইঞ্জিনে খুঁজে পাওয়া যাবে এবং মোবাইলে "অ্যাপ" হিসেবেও ইনস্টল করা যাবে (PWA)।

**ISSN 3006-8088 · One to One School এর অধিভুক্ত**

## ফিচার সমূহ

- **তিনটি মূল বিভাগ:** পিয়ার রিভিউড আর্টিকেল, কনফারেন্স আর্টিকেল, গবেষণা বই — প্রতিটির নিজস্ব ক্যাটাগরি (রাজনীতি, অর্থনীতি, ধর্ম, ভাষা, সাহিত্য, আইন ইত্যাদি, অ্যাডমিন নতুন ক্যাটাগরি যোগ করতে পারবেন)
- **শুধু অ্যাডমিন কনটেন্ট আপলোড করতে পারবেন;** সাধারণ ইউজার শুধু পড়তে ও কমেন্ট করতে পারবেন
- **সাইটে ঢোকার জন্য কোনো লগইন লাগবে না** — সরাসরি সাইটে ঢুকে অ্যাবস্ট্রাক্ট পড়া যাবে
- **সম্পূর্ণ প্রবন্ধ পড়তে (Google Drive লিংক ওপেন করতে) প্রথমবার** হোয়াটসঅ্যাপ নাম্বার, বর্তমান ঠিকানা, এফিলিয়েশন ও ইমেইল দিতে হবে; এরপর থেকে শুধু "প্রবেশ" বাটনে ক্লিক করলেই হবে (কুকিতে মনে রাখা হয়)
- **কমেন্ট সিস্টেমেও একই নিয়ম** প্রযোজ্য; সব কমেন্ট পাবলিকভাবে দেখা যাবে
- **ইউজার নিজে প্রবন্ধ/কনফারেন্স পেপার/গবেষণা বই জমা (Submit) দিতে পারবেন** — একই এক-বার-তথ্য-দেওয়া নিয়মে; জমা দিলে `onetoonejournal@gmail.com`-এ ইমেইল যাবে এবং ওয়েবসাইটেই সংরক্ষিত হবে
- **"আমার সাবমিশন" পাতায় গবেষক নিজের জমার অগ্রগতি (progress bar) দেখতে পারবেন**; অ্যাডমিন ড্যাশবোর্ড থেকে অ্যাডমিন সেই অগ্রগতি ম্যানুয়ালি আপডেট করলে গবেষক তা সাইটে ও (ইমেইল সেটআপ থাকলে) ইমেইলে দেখতে পাবেন
- **অ্যাডমিন ড্যাশবোর্ডে:**
  - প্রতিটি প্রবন্ধ প্রতিদিন কতজন এবং কোন অ্যাকাউন্ট থেকে পড়েছে তার হিসাব
  - নিবন্ধিত ইউজারদের সম্পূর্ণ তালিকা (নাম্বার, ইমেইল, ঠিকানা, এফিলিয়েশন)
  - প্রতি প্রবন্ধ অনুযায়ী সব কমেন্ট একসাথে দেখা ও মুছে ফেলার সুবিধা
  - ক্যাটাগরি ও প্রবন্ধ ম্যানেজমেন্ট (যোগ/সম্পাদনা/মুছে ফেলা)
- **PWA:** মোবাইলে "Add to Home Screen" দিয়ে অ্যাপের মতো ইনস্টল করা যাবে
- **SEO-ready:** সার্ভার-সাইড রেন্ডারিং, sitemap.xml ও robots.txt, তাই গুগল সার্চে ইনডেক্স হবে
- **কোনো পেইড ডেটাবেজ লাগবে না** — এটি একটি সাধারণ JSON ফাইলে ডেটা রাখে, তাই যেকোনো ফ্রি হোস্টিং-এ চালানো যায়

## ১. লোকাল কম্পিউটারে চালানো

```bash
# ১) ডিপেন্ডেন্সি ইনস্টল করুন
npm install

# ২) .env ফাইল তৈরি করুন
cp .env.example .env
# .env ফাইলে ADMIN_USERNAME, ADMIN_PASSWORD, SESSION_SECRET বসিয়ে দিন

# ৩) প্রাথমিক ডেটা (অ্যাডমিন অ্যাকাউন্ট + ডিফল্ট ক্যাটাগরি) তৈরি করুন
npm run seed

# ৪) সার্ভার চালু করুন
npm start
```

এরপর ব্রাউজারে যান: `http://localhost:3000`
অ্যাডমিন প্যানেল: `http://localhost:3000/admin/login`
(`.env`-এ যে ইউজারনেম/পাসওয়ার্ড দিয়েছেন সেটি দিয়ে লগইন করুন, এবং লগইনের পর সেটিংস থেকে পাসওয়ার্ড বদলে ফেলুন)

### সাবমিশন ইমেইল চালু করা (ঐচ্ছিক কিন্তু সুপারিশকৃত)

ইউজার কোনো প্রবন্ধ/বই জমা দিলে সেটা স্বয়ংক্রিয়ভাবে `onetoonejournal@gmail.com`-এ ইমেইল হিসেবে যাবে — যদি আপনি `.env`-এ ইমেইল সেটআপ করে থাকেন। সেটআপ না করলেও সমস্যা নেই: সাবমিশন ঠিকই সাইটে জমা থাকবে এবং অ্যাডমিন ড্যাশবোর্ডে (`/admin/submissions`) দেখা যাবে, শুধু ইমেইল নোটিফিকেশনটা যাবে না।

সেটআপ করতে চাইলে:
1. যে Gmail একাউন্ট থেকে ইমেইল পাঠাতে চান (যেমন `onetoonejournal@gmail.com`), সেখানে গিয়ে **Google Account → Security → 2-Step Verification** চালু করুন (চালু না থাকলে)
2. এরপর **App passwords** অপশনে গিয়ে একটা নতুন App Password তৈরি করুন (Gmail নিজের পাসওয়ার্ড দিয়ে SMTP কাজ করে না, App Password লাগবে)
3. `.env` ফাইলে বসান:
   ```
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=465
   SMTP_USER=onetoonejournal@gmail.com
   SMTP_PASS=(এই App Password টি বসান)
   SMTP_FROM=onetoonejournal@gmail.com
   SUBMISSION_NOTIFY_EMAIL=onetoonejournal@gmail.com
   ```
4. সার্ভার রিস্টার্ট করুন

এই একই ইমেইল সিস্টেম ব্যবহার করে, অ্যাডমিন কোনো সাবমিশনের অবস্থা (status) আপডেট করলে গবেষককেও একটা ইমেইল যাবে জানিয়ে যে তার প্রবন্ধের অগ্রগতি বদলেছে।

## ২. প্রজেক্ট স্ট্রাকচার সংক্ষেপে

```
server.js          → মূল অ্যাপ স্টার্ট হয় এখান থেকে
db.js               → data/db.json ফাইলে ডেটা পড়া/লেখার হেল্পার
auth.js             → পাসওয়ার্ড হ্যাশিং (Node-এর নিজস্ব crypto ব্যবহার করে)
routes/site.js      → পাবলিক পাতা (হোম, ক্যাটাগরি, প্রবন্ধ, সার্চ)
routes/api.js       → "প্রবেশ" গেট ও কমেন্টের API
routes/admin.js     → অ্যাডমিন লগইন, ড্যাশবোর্ড, কনটেন্ট ম্যানেজমেন্ট
views/              → EJS টেমপ্লেট (HTML পেজ)
public/             → CSS, JS, PWA manifest ও আইকন
data/db.json        → সব ডেটা এখানে জমা থাকে (প্রবন্ধ, পাঠক, কমেন্ট...)
```

কনটেন্ট আপলোডের সময় শুধু ইংরেজি Abstract ও Google Drive লিংক দিতে হবে; সম্পূর্ণ প্রবন্ধ (PDF ইত্যাদি) নিজে থেকে Google Drive-এ রেখে সেই লিংক এখানে বসিয়ে দিতে হবে।

## ৩. ফ্রি হোস্টিং-এ ডিপ্লয় করা

এই অ্যাপ ডেটা রাখে একটি সাধারণ ফাইলে (`data/db.json`), তাই **হোস্টিং বাছাই করার সময় সবচেয়ে গুরুত্বপূর্ণ বিষয় হলো — হোস্টিং-এ পার্সিস্টেন্ট (স্থায়ী) স্টোরেজ আছে কিনা।** এখানে দুটি রাস্তা দেওয়া হলো:

### অপশন ক (সবচেয়ে নির্ভরযোগ্য, সম্পূর্ণ ফ্রি): Oracle Cloud "Always Free" VM

Oracle Cloud-এর Always Free টায়ারে একটি ছোট ভার্চুয়াল সার্ভার (VM) সারা জীবনের জন্য বিনামূল্যে পাওয়া যায়, যেখানে ডিস্ক স্থায়ী থাকে (রিস্টার্ট করলে ডেটা মুছে যায় না)। এটি জার্নালের জন্য সবচেয়ে নিরাপদ অপশন যেহেতু ডেটা ফাইলে জমা থাকে।

সংক্ষিপ্ত ধাপ:
1. Oracle Cloud-এ ফ্রি অ্যাকাউন্ট খুলুন এবং একটি "Always Free" Compute VM তৈরি করুন (Ubuntu)
2. VM-এ Node.js ইনস্টল করুন (`sudo apt install nodejs npm` অথবা NodeSource স্ক্রিপ্ট)
3. এই প্রজেক্টের কোড VM-এ আপলোড করুন (git clone অথবা scp দিয়ে)
4. `npm install`, `npm run seed`, তারপর `pm2 start server.js --name journal` দিয়ে সবসময় চালু রাখুন (`npm i -g pm2`)
5. একটি ফ্রি ডোমেইন (যেমন Freenom-এর বদলে .xyz/.site সস্তা ডোমেইন, বা প্রথমে শুধু VM-এর পাবলিক IP ব্যবহার করুন) সেট করে nginx দিয়ে রিভার্স প্রক্সি ও ফ্রি SSL (Let's Encrypt/Certbot) বসিয়ে দিন

### অপশন খ (সবচেয়ে দ্রুত শুরু করার জন্য): Render / Railway ফ্রি টায়ার

Render বা Railway-তে GitHub রিপোজিটরি কানেক্ট করলেই কয়েক ক্লিকে সাইট লাইভ হয়ে যায় এবং একটি ফ্রি সাবডোমেইন (যেমন `one-to-one-journal.onrender.com`) পাওয়া যায়। **তবে সতর্কতা:** এই ফ্রি টায়ারগুলোর ফাইল সিস্টেম "ephemeral" — মানে অ্যাপ রিস্টার্ট বা নতুন ডিপ্লয় হলে `data/db.json`-এ রাখা প্রবন্ধ, পাঠক ও কমেন্টের ডেটা মুছে যেতে পারে। এটি শুরুতে ডেমো/টেস্টিং-এর জন্য ভালো, কিন্তু আসল ব্যবহারের আগে হয় (ক) অপশন ক-তে চলে যান, অথবা (খ) `data/db.json`-কে নিয়মিত ব্যাকআপ/ডাউনলোড করে রাখুন, অথবা (গ) ভবিষ্যতে একটি ফ্রি external database (যেমন Neon/Supabase-এর ফ্রি Postgres) যোগ করে কোডটুকু আপডেট করুন।

Render-এ ডিপ্লয়ের ধাপ:
1. এই কোড একটি GitHub রিপোজিটরিতে পুশ করুন
2. render.com-এ "New Web Service" নিয়ে রিপোজিটরি সিলেক্ট করুন
3. Build command: `npm install && npm run seed`, Start command: `npm start`
4. Environment variেবলে `SESSION_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `NODE_ENV=production` বসিয়ে দিন
5. ডিপ্লয় হলে একটি ফ্রি `.onrender.com` লিংক পাবেন

### ডোমেইন নাম

শুরুতে হোস্টিং প্রোভাইডারের দেওয়া ফ্রি সাবডোমেইন (যেমন `.onrender.com` বা VM-এর IP) দিয়েই কাজ চালানো যাবে। পরে চাইলে সস্তা `.com`/`.org` ডোমেইন কিনে DNS-এ পয়েন্ট করে দিলেই "one-to-one-journal" নিজস্ব নামে চলে আসবে।

## ৪. নিরাপত্তা সংক্রান্ত জরুরি পরামর্শ

- ডিপ্লয় করার আগে `.env`-এ অবশ্যই শক্তিশালী `SESSION_SECRET` ও নতুন `ADMIN_PASSWORD` বসান
- প্রথমবার লগইন করেই অ্যাডমিন সেটিংস থেকে পাসওয়ার্ড বদলে ফেলুন
- `data/db.json` ফাইলটি নিয়মিত ব্যাকআপ রাখুন (এতে সব পাঠকের ব্যক্তিগত তথ্য যেমন হোয়াটসঅ্যাপ নাম্বার, ইমেইল, ঠিকানা জমা থাকে — তাই এই ফাইলটি কখনো পাবলিকভাবে শেয়ার/প্রকাশ করবেন না)
- প্রোডাকশনে `NODE_ENV=production` রাখুন যাতে সেশন কুকি নিরাপদভাবে (HTTPS-only) কাজ করে

## ৫. ভবিষ্যতে যোগ করা যেতে পারে এমন ফিচার

- পাঠকদের জন্য ইমেইল/হোয়াটসঅ্যাপে OTP ভেরিফিকেশন (এখন শুধু তথ্য নেওয়া হয়, যাচাই করা হয় না)
- সরাসরি সাইটে PDF আপলোড ও ভিউয়ার (এখন Google Drive লিংকের উপর নির্ভরশীল)
- একাধিক অ্যাডমিন/এডিটর অ্যাকাউন্ট ও রোল-ভিত্তিক অনুমতি
- CSV এক্সপোর্ট (নিবন্ধিত ইউজার তালিকা, পঠন পরিসংখ্যান)
- বড় পরিসরে ব্যবহারের জন্য JSON ফাইলের বদলে প্রকৃত ডেটাবেজ (PostgreSQL) ব্যবহার
